---
title: FOA：在手机上写 Flutter，直接打出 APK
description: 一个原生运行在 Android 上的 Flutter IDE，设备内自带 SDK、容器和构建链
---
[FOAIDE](https://github.com/haothtrteen/FOAIDE)（Flutter on Android IDE）想验证一件事：**不带电脑，能不能把 Flutter 应用从写代码一路做到装到手机上。**

结论是可以。它不需要 root，也不需要外接设备。

## 结构

```
Android 设备（arm64，无 root）
  FOA App（Flutter）
    ├─ 代码编辑器 / 设计器 / 清单编辑
    ├─ Web 热重载预览
    └─ 构建编排
         ↓ fork/exec
  proot 容器（Debian bookworm arm64）
    ├─ Flutter SDK / Dart
    ├─ Android SDK / Gradle
    └─ 你的工程 → 产出 APK
```

关键点在于用一个 proot 容器把整套构建链搬进手机：Debian rootfs 里装 Flutter SDK、Android SDK 和 Gradle，App 负责编排构建流程。x64 工具（比如 `gen_snapshot`）通过 QEMU 做指令翻译，这样 arm64 设备也能跑通原本只提供 x64 版本的构建组件。

## 为什么这么做

移动端开发的痛点从来不是"写代码"，而是**验证链路太长**：改一行，推到电脑，编译，装包，再回来看效果。FOA 把这段压缩到了同一条设备上：

- **Web 热重载预览**：改代码即时看效果，不用完整重编译
- **设备内构建**：确认没问题，直接产出 APK
- **清单可视化编辑**：`AndroidManifest.xml`、权限、图标这些不用手写

代价是首次安装体积较大（要带 SDK 和 rootfs），构建速度也受限于手机性能。但对"随时改一点、随时看到结果"这个场景，它的体验比来回传包好得多。

## 现在的状态

编辑器、预览、构建三条链路都已打通，能在真机上产出可安装的 APK。后续主要想做的是构建缓存优化——Gradle 冷启动太慢，把常用依赖预置进 rootfs 应该能省掉不少等待。
