IWPhone 是我做得最久的一条线，从最早的安卓端工具箱，扩展成了现在的三块：PC 端工具箱、免 root 模块管理器，以及一个跑在浏览器里的网页版。

三者的共同点是：**尽量不依赖电脑、不依赖 root，把玩机的门槛降下来。**

## IWPhone Toolbox：PC 端

[IWPhone](https://github.com/haothtrteen/IWPhone) 是基于 WPF（C#）写的桌面工具箱，主要解决"手机上不好操作、电脑上更顺手"的那部分工作。它不是一个单点工具，而是把玩机过程中零散的操作收进一个界面：

| 模块 | 能力 |
|---|---|
| 设备信息 | 型号、品牌、系统版本（Android / MIUI / ColorOS）、内核、内存与存储、电池健康度 |
| 投屏 | 基于 scrcpy 的电脑投手机，支持鼠标键盘反向控制；手机投电脑可作副屏 |
| 驱动与依赖 | 自动识别 ADB / 厂商驱动，一键安装修复；自动拉取 Fastboot、Magisk 工具包 |
| 应用管理 | APK 安装卸载、含私有目录的整包备份与还原、系统预装应用的冻结与精简 |
| 插件仓库 | 基于 C# MEF 的动态插件加载，字体替换、主题美化这类功能都做成插件 |
| 安全工具 | Bootloader 解锁引导、第三方 Recovery 刷入、恶意软件与漏洞扫描 |

技术上是 WPF + C# 通过 ADB 协议和设备通信，功能按插件拆分，启用或禁用互不影响。官方给的支持范围是 Android 5.1 ~ 14 与 Windows 10 ~ 11。

## IwphoneModules：免 root 模块管理器

[IwphoneModules](https://github.com/haothtrteen/IwphoneModules) 解决的是另一个问题：想做系统级调整（省电、性能调度、动画调速、隐私开关），传统路径是 Root + Magisk，但门槛高、有风险、影响保修。

它通过系统自带的「无线调试」拿到 shell 权限，再配一套运行时来跑免 root 模块。三块能力：

| 能力 | 说明 |
|---|---|
| 自持 adb | 应用内捆绑 adb 二进制，自己配对、自己连接，全程不需要电脑 |
| 模块运行时 | 启停、冲突检测、沙箱记账、配置、日志、开机自启 |
| 兜底机制 | 写前快照，记下原值，一键还原到改动之前 |

模块列表和各模块说明放在[模块目录](/iwphone-modules/)里，随仓库一起更新。

### 全程在手机里完成的引导

```
① 配对设备    通知栏输入配对码（端口由 mDNS 自动发现，不用手抄）
② 部署框架    App 内置框架包，一键部署 / 修复 / 重置
③ 设置访问密钥  自己设一把密钥（WebUI 鉴权，APatch 式）
        ↓
   框架运行 → 装模块 → 管理
```

配对端口用 mDNS 自动发现，连接端口固定在 `persist.adb.tcp.port=5555`，跨重启保持，配合 `BOOT_COMPLETED` 与 JobScheduler 做开机自启。App 用 `jniLibs` 的技巧自带 adb 二进制，绕开 Android 对应用数据目录 `noexec` 的限制。

### 兼容 Magisk 式模块

Magisk / KernelSU / AxManager 的模块结构基本一致，安装时会自动适配：

| 原框架概念 | 本框架的处理 |
|---|---|
| `module.prop` | 生成等价元信息（含 `runtime=0` 标记常驻） |
| `service.sh` | 生成兼容入口，接进启动流程 |
| `post-fs-data.sh` | 启动时尽力执行，语义差异在文档里标明 |
| `action.sh` / `uninstall.sh` | 原样支持 |
| `webroot/` 每模块 WebUI | 按 `/mod/<模块名>/` 提供，注入同构的 `ksu` 桥 |
| BusyBox applet 假设 | 自带 BusyBox（358 个 applet），PATH 优先指向它 |

明确不支持的是 systemless 挂载、Zygisk / 内核模块、需要 `su` 的模块——这些在免 root 环境里物理上做不到。安装前会预检并给出判定：预计兼容 / 需要 Root / 无法判断。

### 写前快照

免 root 玩机最怕的不是"没效果"，而是**改坏了回不去**。框架在沙箱的写操作拦截点上多做了一步：首次写某个系统资源前，记录它的原值。

```
$IWPHONE_ROOT/modsnap/<模块名>.snap
settings put global window_animation_scale '1.0'   # [global.window_animation_scale]
```

每行本身就是一条可直接执行的还原命令。点「还原」时会先展示清单（当前值 → 还原值），确认后**先停模块再还原**——常驻模块的守卫循环会把值改回去，不停模块等于白还原。

卸载模块不会删除快照，所以模块可以卸，它改过的设置仍能还原。

## webiwphone：网页版

最早的那批页面（`webadb.html`、`appops.html`、`iwhl.html`）原本挂在这个域名下，纯前端实现，用 WebUSB 连接设备。现在这部分已经迁到 IWPhone 仓库的 `webiwphone/` 目录里，和 PC 端放在一起维护。

三条线各有分工：桌面端管复杂度高的操作，模块管理器管需要持续运行的调整，网页版管"随手打开就能用"的场景。
